# 读者优先的业务文档写作

目标不是把已有材料写得更漂亮，而是先把业务想清楚，再让不同读者以尽可能低的成本知道：整体发生了什么、为什么、与自己有什么关系、接下来要决定或完成什么。

## 先定义文档产品

动笔前，从上下文中识别：

- **场景**：公司级汇报、内部复盘、方案决策、项目同步、述职或其他；
- **读者角色**：谁负责决策，谁需要协作，谁只需同步；
- **读者任务**：每类读者最关心的问题、能够采取的行动；
- **沟通结果**：同步认知、展示结果、定位问题、获得决策、申请资源或指导执行；
- **唯一主线**：读者离开后最应该记住的一项判断。

多类读者同时存在时，先找到共同需要的业务全貌，再把角色专属信息放在相关结论旁或单列“决策与支持”。不要为每类读者重复写一遍全文。

信息不足但不影响主线时，做最小合理假设并标注；只有缺失信息会改变核心判断或结构时才追问。

## 选择视角，而非套用一种模板

- **需求视角优先**：公司级、跨团队或面向不熟悉业务的读者时，围绕他们需要理解和决定的业务问题组织，不按组织架构或素材来源拼接。
- **供给视角可用**：团队内部查漏补缺、执行复盘或职责盘点时，可以按流程、职能或工作模块展开，但仍需先交代整体状态和关键问题。

根据任务选择结构：

- **方案/决策**：业务目标与约束 → 现状和问题 → 备选方案与取舍 → 建议 → 行动；
- **项目/周报**：总体状态 → 关键变化 → 风险与原因 → 下一步与求助；
- **经营或周期复盘**：整体表现 → 驱动与阻力 → 关键专题下钻 → 决策、行动与支持。此类任务必须读取 [references/business-review-method.md](references/business-review-method.md)；
- **内部执行复盘**：目标与结果 → 流程/职能拆解 → 问题定位 → 责任与改进。

结构服务于读者的认知顺序，可以删改，不机械补齐章节。

## 选择与组织信息

先做充分分析，再收敛呈现。素材来源、部门边界和写作者分工都不能自动成为文档目录。

- 开头用几行或“一分钟速览”给出核心结论、关键结果/风险、需要的决定或下一步；
- 先给业务全局，再进入细节；先写结果和判断，再写过程；
- 标题优先写成观点、变化或状态，不使用只有“背景”“数据”“进展”的空标签；
- 同层内容保持同一种分类维度，使用 H1/H2/H3 形成可扫读的目录树；
- 只保留能改变理解、判断或行动的信息。拿不准时问：删掉后是否造成明显损失？若不能明确回答“会”，先删掉；
- 深度取决于读者任务：后台分析可以很深，前台呈现只展示读者需要的结论和必要证据。

多人供稿时，指定一位能理解业务全局的首席作者负责主线、取舍和一致性。不要让汇总者只做材料拼接。

## 写目标、结果与因果

- 目标写成对用户、业务或组织产生的结果，不把上线、接入、建设、覆盖等过程产出当作最终目标；
- 用具体、可衡量、相关且有时间边界的方式表达目标，并补足基线、目标值、竞品/行业水平或理想终点；
- 重要结果不仅回答“变了多少”，还要回答主要动力、阻力、可控因素和下一步；
- 用业务公式、价值链或因果链拆解结果，选择最能暴露真实问题的维度，而不是最方便取数的维度；
- 每项关键动作都应能解释如何推动目标；过程指标用于解释贡献，不单独冒充成绩；
- 关注偏离预期的结果和影响长期增长的慢变量，而不是平均分配篇幅。

定性或支持性工作也应提炼价值链、能力轴或关键动作，但不要为了套公式制造虚假量化。

## 写数据与证据

重要数据至少说明：变化、参照、含义、可能原因和行动。明确区分事实、作者判断和待验证假设，不为了顺滑而编造结论。

精度和单位服务于决策：

- 无必要时用易读、易记的合理精度，如 `35%` 而不是 `34.87%`；
- 同一比较范围统一数量级、币种、时间口径、百分比口径和图例；
- 需要审计、结算或精确比较时保留原始精度，并说明数据口径。

## 让表达无歧义

- 名称精确到对象和边界，同一概念全文只使用一个名称；
- 首次出现的缩写、内部黑话和项目名要解释，能用直白名称就不用抽象简称；
- 使用明确日期，不写会随阅读时间变化的“本周三”“下周五”；
- 每段只承担一个主要任务，尽量按“结论 + 证据/解释 + 行动”表达；
- 抽象判断落到事实、数据、用户场景或可观察行为，避免无法验证的套话。

## 用视觉降低认知成本

当文字迫使读者在脑中重建对象、流程或关系时，选择图片、流程图、表格或图表。视觉必须有标题、口径或注释，并直接支持正文判断。

可用红/黄/绿或等价状态帮助扫读：红=卡点/下降/事故，黄=需关注，绿=完成/改善/上线。通篇保持图例语义一致，并配合文字标签，不能只靠颜色传达信息。

## 工作模式与交付

- **从零撰写**：先提炼主线、业务结构、证据和行动，再成文，不按素材出现顺序照抄；
- **重构改写**：保留事实、数据和原意，重排结构、补出可证实的逻辑，标注无法确认的内容；
- **审阅诊断**：先指出最影响理解或决策的问题，再给可直接替换的写法，不只做语言评价。

交付前读取 [references/review-checklist.md](references/review-checklist.md)，选择相关检查项。优先修复会改变理解、判断或行动的问题，再润色语句。

最终结果应通过四项测试：

- **30 秒测试**：只看摘要和标题，能否知道整体状态和主结论；
- **三个问题测试**：是否回答了核心读者最可能提出的三个问题；
- **删除测试**：留下的信息是否都影响理解、判断或行动；
- **深度测试**：呈现的是读者需要的结论，而不是作者尚未收敛的分析过程。
